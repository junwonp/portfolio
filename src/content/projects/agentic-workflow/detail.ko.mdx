## 워크플로우 개요

**"고속 변경의 시대에 코드 안정성을 담보하기 위해 정형화된 회귀 방지(Regression Prevention) 장치를 설계합니다."**

이 워크플로우는 빠른 구현 코드 생성이 보편화되는 환경에서, **제품의 타입 무결성, 테스트 안정성, 실제 브라우저 렌더링 정밀도**를 유지하기 위해 구축한 엄격한 검증 시스템입니다. 변경 사항이 발생할 때마다 정적 분석, 린트 검사, 자동화 테스트, 실제 UI 렌더링 검증, 그리고 최종 논리적 diff 리뷰를 게이트웨이로 두어 회귀 버그의 유입을 철저히 차단합니다.

개발자는 아키텍처 모델링과 도메인 요구사항 정의, 트레이드오프 결정 등 상위 수준의 결정에 온전히 집중하며, 기계적인 구현과 보일러플레이트 작성 이후의 검증 과정을 자동화된 가드레일 아래에서 통제합니다.

### 핵심 개념

- **지휘관 권한 (Conductor Authority):** 아키텍처의 설계, 데이터 모델링, 예외 처리 설계 및 최종 코드 승인 권한은 엔지니어가 100% 소유합니다.
- **엄격한 회귀 방지 (Regression Prevention):** 정적 검사(`tsc`), 코드 품질 검사(`eslint`), 단위 테스트(`vitest`), 브라우저 UI 검증을 유기적으로 연계하여 변경 시점의 코드 무결성을 담보합니다.
- **컨텍스트 격리 (Context Budgeting):** 작업에 불필요한 전역 규칙을 배제하고 범위가 좁게 제한된 맥락(Scoped Context)만 로드하여 불확실성을 최소화하고 정밀한 변경을 유도합니다.
- **고가치 엔지니어링 리디렉션 (Value Redirection):** 반복적인 구현 리소스를 절약하여 브라우저 렌더링 최적화, 보안성 검토, 타입 설계 고도화 등 고차원적 문제 해결에 집중 투자합니다.

**검증 가드레일**

| 단계 | 기준 | 실패 시 처리 |
| --- | --- | --- |
| 컨텍스트 확인 | 관련 파일과 기존 패턴을 먼저 읽음 | 추측 구현 금지, 파일 재확인 |
| 컨텍스트 예산 | 전역/프로젝트 스킬을 분리해 필요한 지침만 로드 | 불필요한 규칙은 작업 컨텍스트에서 제외 |
| 구현 범위 | 요청과 직접 연결된 파일만 수정 | unrelated diff 분리 |
| 정적 검증 | `pnpm check`, `pnpm lint` 통과 | 실패 로그 기반으로 수정 |
| 콘텐츠 검증 | 언어별 detail, alt, caption, 링크 동기화 | 한쪽 언어만 바뀐 변경 차단 |
| 브라우저 검증 | 로컬 페이지에서 실제 렌더링 확인 | DOM/스크린샷 기준으로 재수정 |
| 커밋 검토 | diff를 논리 단위로 분리 | 섞인 변경은 커밋 전 분리 |

**실제 적용 예시**

- **복잡한 플랫폼 마이그레이션 (Next.js ➡️ Cloudflare Workers/vinext):** Next.js의 대규모 App Router 구조를 vinext로 마이그레이션할 때, 라우팅 세그먼트와 레이아웃 구조의 정합성을 `tsc` 및 통합 테스트 게이트로 교차 검증하여 무중단 전환을 달성했습니다.
- **웹 성능 튜닝 및 회귀 방지 (LCP/INP 최적화):** 스크롤 기반 인터랙티브 모션과 이미지 레이지 로딩을 추가하며 발생할 수 있는 레이아웃 시프트(CLS)를 자동화된 브라우저 스크린샷 검증으로 사전 감지하여 성능 점수를 안정적으로 유지했습니다.
- **데이터베이스 스키마 변경 안정성 확보 (D1 SQLite 스키마 업데이트):** 로컬 D1 데이터베이스 스키마 변경 시, 애플리케이션 서비스 레이어의 테스트 케이스를 자동 실행하여 스키마 불일치로 인한 런타임 크래시를 커밋 전에 100% 차단했습니다.

### 자가 진단 및 복구 루프 (Self-Diagnosis & Auto-Recovery)

에러 발생 시 사람이 개입하는 대신 컴파일러나 테스트 도구(`vitest`)의 원시 로그를 에이전트에 환류시킵니다. 에이전트는 **[로그 분석 ➡️ 가설 검증 ➡️ 코드 수정]** 루프를 통과할 때까지 스스로 실행하여 버그를 자율 수정합니다.

### 다중 에이전트 협업 및 역할 분할 (Multi-Agent Orchestration)

복잡한 작업은 단일 모델에 맡기지 않고 구현(`tdd-guide`), 품질 검수(`code-reviewer`), 보안성 감사(`security-reviewer`) 등으로 역할을 나눈 서브 에이전트들을 구동하여 컨텍스트 노이즈를 억제하고 신뢰성을 높입니다.

## 회고

**핵심 가치는 단순한 속도가 아닙니다.** 반복 작업을 리뷰 가능한 단위로 나누고, 각 변경이 안전하다는 근거를 남기는 것이 더 중요했습니다.

**AI는 엔지니어링 판단을 대체하지 않습니다.** 컨텍스트, 범위, 검증을 명시적으로 관리할 때만 이 흐름이 제대로 작동합니다. 이 부분이 코드 리뷰나 면접에서 설명 가능한 강점입니다.
