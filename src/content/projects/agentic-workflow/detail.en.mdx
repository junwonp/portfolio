## Workflow overview

**"Designing structured regression prevention to guarantee code stability in the age of rapid implementation."**

This workflow is a strict verification system built to maintain **"type integrity, test stability, and browser rendering precision"** in an environment where fast code generation is common. Every change must pass through automated static checks, lint inspections, unit tests, browser UI rendering validation, and a final logical diff review to prevent regression bugs from entering production.

The developer remains the director—focusing on architectural modeling, domain requirements, and business trade-offs—while controlling the verification of mechanical implementations under automated guardrails.

### Core Concepts

- **Conductor Authority:** Architectural modeling, data schemas, exception strategies, and final code approval remain strictly owned and verified by the engineer.
- **Strict Regression Prevention:** Seamlessly connects static analysis (`tsc`), quality checks (`eslint`), unit testing (`vitest`), and browser UI validation to guarantee code integrity at the point of change.
- **Context Budgeting:** Decouples global rules from task-specific directives, loading only scoped context to eliminate noise and ensure highly accurate edits.
- **High-Value Redirection:** Reclaims hours spent on repetitive implementation to invest in rendering optimization, security audits, and advanced type safety.

**Verification guardrails**

| Step | Standard | If it fails |
| --- | --- | --- |
| Context gathering | Read relevant files and existing patterns first | Stop guessing and inspect the source |
| Context budget | Split global and project skills so only necessary rules are loaded | Remove unrelated directives from the task context |
| Scope control | Touch only files directly tied to the request | Split unrelated diffs before commit |
| Static validation | Pass `pnpm check` and `pnpm lint` | Fix from logs, not blind retries |
| Content validation | Keep localized detail, alt, caption, and links in sync | Block one-locale-only changes |
| Browser validation | Verify the rendered local page | Rework from DOM/screenshot evidence |
| Commit review | Separate logical diff groups | Split mixed concerns before commit |

**Concrete examples**

- **Complex Platform Migration (Next.js ➡️ Cloudflare Workers/vinext):** When migrating the codebase to vinext on Cloudflare Workers, we verified routing segments and layouts through `tsc` and integration test gates, ensuring a regression-free transition.
- **Performance Tuning & Layout Regression Prevention (LCP/INP Optimization):** Verified that dynamic scroll animations and optimized image loading did not introduce Layout Shifts (CLS) using automated browser rendering checks, preserving Core Web Vitals.
- **Database Schema Update Integrity (D1 SQLite Updates):** Guarded SQL schema migrations by automatically running the application integration test suite, preventing runtime crashes from schema mismatches before any commit.

### Self-Diagnosis & Auto-Recovery Loop

Instead of manual debugging, raw logs from compilers or test runners (`vitest`) are fed back to the agent. The agent runs an autonomous loop—**[Analyze Logs ➡️ Formulate Hypothesis ➡️ Correct Code]**—until all gates pass.

### Multi-Agent Orchestration & Task Isolation

Instead of a single general-purpose prompt, complex tasks are delegated to specialized sub-agents—such as design (`tdd-guide`), quality review (`code-reviewer`), and security auditing (`security-reviewer`)—minimizing context noise.

## Retrospective
