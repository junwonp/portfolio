## 프로젝트 소개

**"SaaS 운영을 위한 재사용 가능한 백오피스 패턴"**

계정, 구독, 제품 사용량, 매출 모니터링을 다루는 내부 B2B SaaS 관리자 대시보드 프로젝트입니다. 사내 운영 시스템이기 때문에 실제 화면과 원본 비즈니스 데이터는 공개할 수 없어, 이 페이지에서는 프론트엔드 구조와 재사용 가능한 운영 화면 패턴을 중심으로 정리했습니다.

핵심은 특정 화면 하나가 아니라 반복되는 운영 흐름이었습니다. 데이터를 목록으로 확인하고, 검색/필터링하고, 상세 레코드를 확인하고, 생성/수정한 뒤, 사용량과 매출 신호를 같은 맥락에서 모니터링하는 흐름입니다. 이 영역을 **TypeScript**, **React**, **React Table**, **MUI**, **TanStack Query**, **Chart.js** 기반으로 구축했습니다.

## 회고

이 프로젝트는 공개 사용자용 제품 사례라기보다, 회사 내부에서 자주 필요한 운영 도구를 안정적으로 구축할 수 있음을 보여주는 사례입니다. 복잡한 테이블, 필터, 폼, 차트 등 내부 시스템은 화려함보다 상태 관리의 예측 가능성과 유지보수 가능한 컴포넌트 경계가 더 중요하기 때문입니다.

특히 페이지가 늘어남에 따라 각 화면이 독자적인 테이블과 필터, Mutation 흐름을 갖게 되면 유지보수 비용이 급격히 증가합니다. 그래서 다음과 같은 설계 규칙을 의식적으로 도입했습니다:

- 상태 경계 명확화: <strong>query state → table state</strong>의 단방향 데이터 흐름을 채택해, TanStack Query의 서버 상태와 React Table의 UI 상태가 충돌하지 않도록 설계했습니다. 예를 들어 필터/정렬은 query key로 묶어 서버-사이드 페이징과 일관되게 동작하도록 했고, 선택된 행/편집 중인 로컬 폼 상태는 오직 테이블 컴포넌트 내부에서만 관리하도록 했습니다.
- 트레이드오프 문서화: 대안(예: AG Grid)의 장점과 단점을 문서화해 팀이 빠르게 결정을 재현할 수 있게 했습니다. 초기에는 고성능 그리드 도입을 검토했지만, 번들 사이즈와 디자인 일관성(관리자 시스템 내 MUI 사용)으로 인해 React Table을 선택했고, 고성능 가상화는 필요에 따라 react-virtual을 조합하는 방식으로 보완했습니다.
- 공통 CRUD 패턴의 도입: 목록 → 상세 → 생성/수정의 상호작용 모델을 표준화하여 신규 관리 화면 개발 속도를 크게 향상시켰습니다. 결과적으로 패턴 적용 전에는 신규 관리자 페이지 하나를 만드는 데 평균 3일이 걸렸다면, 공통 패턴 도입 후에는 약 반나절 수준으로 단축되었습니다.

이 경험은 '복잡성을 단순화하는 설계'가 운영 도구의 가용성과 팀 생산성에 직접적인 임팩트를 준다는 점을 명확히 보여주었습니다.
