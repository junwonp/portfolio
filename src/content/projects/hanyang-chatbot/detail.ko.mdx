## 프로젝트 소개

**"스크립트 한 줄로 임베드되는 화이트라벨 AI 챗봇 위젯"**

Orca AI의 SaaS형 AI 챗봇 플랫폼에서 한양대학교 창업지원단을 비롯한 여러 고객사 웹사이트에 임베드되는 챗봇 위젯의 프론트엔드를 전담 개발했습니다. 고객사는 `<script>` 태그 한 줄과 `orca.setup(websiteId)` 호출만으로 위젯을 설치할 수 있고, 서버 설정만으로 브랜딩·레이아웃·언어가 자동 적용되는 멀티테넌트 구조입니다.

임베드 위젯의 최대 난제인 "어떤 사이트에 붙여도 깨지지 않는 UI"를 Shadow DOM 기반 스타일 격리로 해결했고, LLM 답변의 토큰 단위 스트리밍 렌더링과 한글 IME 안전 입력까지 구현했습니다.

> 이 서비스는 현재 운영이 종료된 상태입니다.

## 회고

**"임베드 위젯을 처음부터 끝까지 설계한 경험"**

### 1. 처음으로 만든 임베드 위젯 — Shadow DOM과 단일 스크립트 배포

Shadow DOM도, 스크립트 한 줄로 동작하는 위젯도 이 프로젝트에서 처음 만들어봤습니다. 호스트 사이트의 CSS는 통제할 수 없다는 전제에서 출발해, "어디에 붙어도 안 깨지는" 보장은 코드 수정이 아니라 구조(Shadow DOM 격리, 스타일 주입 위치 제어, 단일 번들 산출)에서 나온다는 것을 배웠습니다. 번들 크기, 스타일 격리, 설치 간결성 같은 임베드형 제품의 핵심 제약을 제품 관점에서 이해하게 된 프로젝트였습니다.

### 2. 코드에서 확인되는 아쉬운 점과 개선 방향

- **캐러셀·칩 리스트의 중복 `key`**: `message.children.map`의 `key`가 고정 문자열이라 React 조정 관점에서 잘못된 키였습니다. 지금이라면 `child.id ?? index` 기반 키로 고치겠습니다.
- **`<link>`를 `<style>` 안에 append**: 폰트 `<link>`를 `<style>` 엘리먼트 자식으로 넣은 것은 HTML 스펙상 불안정합니다. Shadow Root에 직접 append하거나 Constructable Stylesheets를 쓰는 것이 정석이었습니다.
- **다크모드 초기값이 항상 light**: OS 다크모드 사용자가 첫 진입 시 라이트로 플래시되는 문제가 있었습니다. `matchMedia('(prefers-color-scheme: dark)')`로 초기값을 잡았어야 했습니다.
- **`useMediaQuery`의 의존성 배열**: `matches`가 바뀔 때마다 리스너를 떼었다 붙이는 구조였습니다. `[query]`만으로 충분하고, 함수형 업데이트가 안전합니다.

### 3. 계약 기반 협업과 프론트엔드 오너십

플랫폼 SDK(`@orca.ai/pulse`) 소비자로서 백엔드 팀과 API 계약 문서를 저장소에 함께 관리하며 병렬 개발했습니다. 이슈 번호 기반 브랜치, PR 리뷰, conventional commit으로 270개 커밋을 관리했고, 프론트엔드 영역은 전담(백엔드 커밋 0건)으로 운영했습니다. RAG 백엔드 구조를 이해한 위에서 SDK를 소비한 경험은 풀스택 문맥을 가진 프론트엔드로 성장하는 밑거름이 되었습니다.
