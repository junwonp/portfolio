## Project Overview

**"An AI chatbot widget embedded with a single script tag"**

As the dedicated frontend engineer at Orca AI's SaaS chatbot platform, I built the embeddable chatbot widget for client websites, including the Hanyang University Startup Support Foundation. Clients install the widget with one `<script>` tag and a single `orca.setup(websiteId)` call, and branding, layout, and language apply automatically from server settings — a fully multi-tenant architecture.

The hardest problem in third-party widgets — "never break, no matter which site it's embedded in" — was solved structurally with Shadow DOM style isolation, along with token-level LLM streaming and Korean IME-safe input.

> This service has since been discontinued.

## Retrospective

**"Designing an embed widget end to end for the first time"**

### 1. My first embed widget — first time with Shadow DOM and single-script delivery

Both Shadow DOM and a widget that runs from a single script tag were firsts in this project. Starting from the premise that host page CSS is uncontrollable, I learned that a host-independent UI comes from structure — Shadow DOM isolation, style-injection placement, a single-bundle artifact — not from patches. This project shaped how I now think about the core constraints of embedded products: bundle size, style isolation, and installation simplicity.

### 2. Why I chose a self-configuring structure keyed by a website ID

To absorb per-customer customization requests (copy, colors, etc.) without touching product code, I chose a multi-tenant structure where the widget configures itself from site settings delivered by the server. The goal was to onboard new customers through site configuration alone, with no product deployments.

### 3. Debugging and QA under embed-environment constraints

Since the host site was beyond my control, I embedded the widget in a dedicated test page to verify standalone behavior first, then narrowed issues on customer pages using browser console logs.
