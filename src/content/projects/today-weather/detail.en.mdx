## Project overview

**"Action-oriented weather recommendations: outfit, umbrella, and mask"**

Weather apps have three common frustrations: global data sources that miss Korea's local forecasts, information scattered across too many screens, and raw numbers that still make the user do the mental math — "is 15°C a jacket or a coat day?" **Today's Weather** uses the most accurate local sources (KMA, Air Korea) and translates the data into immediate action plans: what to wear, whether to take an umbrella, and whether to bring a mask.

### Cache and data flow

Today's Weather is not just a public API client. It is a data pipeline designed around the latency, regional blocking, and rate-limit constraints of Korean public APIs.

1. The app normalizes the user's GPS or IP-based location into coordinates.
2. Next.js Route Handlers run in Vercel's `icn1` region so Korean public APIs can be called from a Korean IP region.
3. Each API route checks Upstash Redis first and returns `fromCache: true` immediately on a cache hit.
4. Only cache misses call KMA, Air Korea, or Kakao, then store the result in Redis with a route-specific TTL.
5. The web and Expo apps consume the same `packages/shared` API client and TanStack Query key factory.
6. The iOS widget calls the same `/api/weather` and `/api/dust` endpoints using the persisted `apiBaseUrl`, `lat`, and `lon`, and skips network refreshes when data was updated within the last 5 minutes.

| Data             | Cache key basis              | TTL        | Why                                                                          |
| ---------------- | ---------------------------- | ---------- | ---------------------------------------------------------------------------- |
| Weather forecast | KMA grid `nx`, `ny`          | 30 minutes | Short-term weather changes often, but this still batches rapid user requests |
| Fine dust        | Coordinates rounded to 0.1°  | 30 minutes | Users in the same area share the same regional air-quality reading           |
| Weather alerts   | Coordinates rounded to 0.1°  | 10 minutes | Alerts can change quickly, so the TTL is shorter                             |
| UV index         | Coordinates rounded to 0.1°  | 1 hour     | UV changes more slowly than current weather                                  |
| Pollen           | Coordinates rounded to 0.1°  | 6 hours    | Published on a slower daily cadence                                          |
| Address label    | Coordinates rounded to 0.01° | 24 hours   | Administrative address labels rarely change                                  |

On the client, TanStack Query uses a 5-minute default `staleTime`, and only successful queries are persisted for up to 24 hours in IndexedDB on web and AsyncStorage on Expo. Returning users see the last successful data immediately while the app revalidates only the queries that need fresh data.

## Retrospective

**Latest tech in production:** Navigating the breaking changes in Next.js 16 and React 19 gave me a hands-on understanding of the modern React ecosystem — including where the React Compiler genuinely reduces boilerplate and where it still requires manual guidance.

**Infrastructure constraints:** IP blocking and rate limiting are real problems that documentation rarely prepares you for. Region-pinning serverless functions and Redis caching were structurally the right fixes, and the exact traffic-reduction percentage will be measured and validated once production traffic data is available.

**Evolution into a Monorepo (Key Takeaway):** Starting with separate web and mobile repositories initially led to frequent bugs and high synchronization costs when manually copy-pasting recommendation logic across codebases. To resolve this, I extracted core business logic and types into `packages/shared` via a pnpm workspace. This single source of truth dramatically reduced cross-platform bugs and accelerated new feature additions, reinforcing that a 'Single Source of Truth for shared logic' is essential for multi-platform applications.

**Cross-platform abstraction:** Sharing business logic across a web app, a mobile app, and an iOS widget without duplication validated the monorepo design. The shared package pattern is now a default in how I structure multi-platform projects.
