### 캐시·데이터 흐름

오늘날씨는 단순히 공공 API를 호출하는 앱이 아니라, 국내 공공 API의 지연·차단·호출 제한을 전제로 설계한 데이터 파이프라인입니다.

1. 사용자의 GPS 또는 IP 기반 위치를 좌표로 정규화합니다.
2. Next.js Route Handler가 Vercel `icn1` 리전에서 실행되어 한국 IP 조건이 필요한 공공 API를 호출합니다.
3. 각 API route는 먼저 Upstash Redis를 조회하고, cache hit이면 `fromCache: true` 응답을 즉시 반환합니다.
4. cache miss일 때만 기상청·에어코리아·Kakao API를 호출한 뒤 Redis에 TTL과 함께 저장합니다.
5. 웹과 Expo 앱은 동일한 `packages/shared` API client와 TanStack Query key factory를 사용해 데이터를 소비합니다.
6. iOS 위젯은 저장된 `apiBaseUrl`, `lat`, `lon`으로 동일한 `/api/weather`, `/api/dust` 엔드포인트를 호출하고, 최근 5분 내 갱신 데이터가 있으면 네트워크 요청을 생략합니다.

| 데이터    | 캐시 키 기준           | TTL    | 이유                                                                    |
| --------- | ---------------------- | ------ | ----------------------------------------------------------------------- |
| 날씨 예보 | 기상청 격자 `nx`, `ny` | 30분   | 초단기 실황·예보가 자주 바뀌지만 사용자 요청을 충분히 묶을 수 있는 단위 |
| 미세먼지  | 좌표 0.1도 반올림      | 30분   | 같은 권역 사용자는 동일한 시도 단위 대기질 데이터를 공유                |
| 특보      | 좌표 0.1도 반올림      | 10분   | 특보는 빠르게 바뀔 수 있어 더 짧게 유지                                 |
| 자외선    | 좌표 0.1도 반올림      | 1시간  | 자외선 지수는 급격히 변하지 않는 데이터                                 |
| 꽃가루    | 좌표 0.1도 반올림      | 6시간  | 일 단위 발표 데이터라 긴 TTL 적용                                       |
| 주소      | 좌표 0.01도 반올림     | 24시간 | 행정동명은 거의 변하지 않으므로 장기 캐시                               |

클라이언트는 TanStack Query의 기본 `staleTime`을 5분으로 두고, 성공한 쿼리만 IndexedDB(웹)와 AsyncStorage(Expo)에 최대 24시간 보존합니다. 그래서 앱 재진입 시에는 이전 성공 데이터를 먼저 보여주고, 백그라운드에서 필요한 쿼리만 다시 검증합니다.

### 현재 제품 상태

- 웹 앱은 Next.js App Router 기반으로 실제 기상청·에어코리아 데이터를 조회하는 상태입니다.
- Expo 앱은 웹과 동일한 공유 패키지를 사용하며, 앱 활성화 시 주요 예보 쿼리를 다시 검증합니다.
- iOS 홈 화면 위젯은 `@bacons/apple-targets`로 Expo 프로젝트 내부에 Swift target을 붙여 구현했습니다.
- 추천 결과는 복장·우산·마스크 판단을 같은 shared logic에서 계산하도록 구성했습니다.
- 로컬 검증 기준으로 web/shared/mobile 테스트와 타입체크가 통과했습니다.
- 남은 보강 지점은 모바일 앱/위젯 실기기 스크린샷과 배포 상태 증거를 추가하는 것입니다.

## 회고

**최신 기술 스택의 실전 도입:** Next.js 16과 React 19 도입 과정에서 발생한 기존 코드와의 호환성 문제를 직접 해결하며 React Compiler가 실제로 보일러플레이트를 줄여주는 경우와 수동 최적화가 여전히 필요한 상황을 체감으로 이해했습니다.

**인프라 제약 조건 해결:** IP 차단과 호출 제한(Rate Limit)은 실제 서비스 운영 시 마주하는 중요 문제입니다. 서버리스 리전 고정과 Redis 캐싱을 통해 안정적인 동작 구조를 확립했으며, 실제 호출 절감률은 향후 운영 트래픽 데이터를 확보하여 객관적으로 검증해 나갈 계획입니다.

**크로스 플랫폼 추상화:** 중복 없이 웹 앱, 모바일 앱, iOS 위젯에서 비즈니스 로직을 공유하는 것이 모노레포 설계의 핵심 가치임을 검증했습니다. 공유 패키지 패턴은 이제 멀티 플랫폼 프로젝트를 구성하는 기본 방식이 되었습니다.
