## Project overview

**"Use AI for speed, keep engineering ownership explicit."**

This workflow is how I use AI tools to move faster on portfolio and product UI work while keeping product judgment, architecture, and final review under my control. It starts from the user-facing outcome and existing code, then constrains the agent with project rules, scoped context, check/lint/test gates, browser verification, and final diff review.

The result is not a tool showcase. It is a repeatable delivery loop for turning AI output into reviewed, tested, and rendered changes that can be defended in an engineering conversation.

**Verification guardrails**

| Step | Standard | If it fails |
| --- | --- | --- |
| Context gathering | Read relevant files and existing patterns first | Stop guessing and inspect the source |
| Context budget | Split global and project skills so only necessary rules are loaded | Remove unrelated directives from the task context |
| Scope control | Touch only files directly tied to the request | Split unrelated diffs before commit |
| Static validation | Pass `pnpm check` and `pnpm lint` | Fix from logs, not blind retries |
| Content validation | Keep localized detail, alt, caption, and links in sync | Block one-locale-only changes |
| Browser validation | Verify the rendered local page | Rework from DOM/screenshot evidence |
| Commit review | Separate logical diff groups | Split mixed concerns before commit |

**Concrete examples**

- **Portfolio positioning:** Reworked the home page so product growth and release ownership stay ahead of AI-tool messaging.
- **Metric cleanup:** Kept metric cards focused on outcome, scale, and measurable improvement instead of years, technology names, or status labels.
- **Browser-based UI verification:** Checked responsive metric layouts, project-detail table styling, and homepage visibility directly in the local browser before marking work complete.
- **Evidence hygiene:** Avoided using screenshots as portfolio evidence unless they came from real product screens or reproducible local output.

## Retrospective

**The main value is not raw speed.** The useful part is breaking repetitive work into reviewable units and leaving behind evidence that each change is safe.

**AI does not replace engineering judgment.** The workflow works only when context, scope, and verification are explicit. That is the part I can defend in a code review or interview.
