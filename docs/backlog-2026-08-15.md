# 백로그 — 2026-08-15 (M3E 감사 후속)

> 사용자 보고 이슈 조사 결과. 전 항목 **기존 코드 문제**로 M3E 감사 변경과 무관함이 확인됨.
> 각 항목에 원인·권장 수정 방향 포함 — 우선순위 순.

## 1. ✅ 해결 (2026-08-15): `**` 마크다운 리터럴 노출

- **원인**: ① achievements `detail`이 마크다운 파싱 없이 sanitize만 거침 ② 히어로 tagline/description이 평문 렌더
- **수정**: `markdownInlineToHtml` 신설(마크다운→HTML, 내부 이스케이프, 기존 HTML 통과) + achievements에 적용 + 히어로에 `RichText(parseMarkdown(...))` 적용. 테스트 4건 추가
- **검증**: 전 프로젝트 브라우저 실측 — 가시 텍스트의 `**` 0건

## 2. ✅ 해결 (2026-08-15): `li::before` 불릿 정렬

- **조사**: TOC는 BaseSideNav 가드로 이미 정상, 본문·achievements 리스트도 실측 정상. 정확한 재현 불가
- **수정(방어적)**: 전역 불릿에 `top: 0.2rem` 고정 추가 — 폰트 메트릭과 무관하게 첫 줄에 정렬
- **참고**: 여전히 깨짐이 보이면 정확한 뷰포트·테마·스크린샷 필요

## 3. ✅ 해결 (2026-08-15): 세로형 스크린샷 크롭

- **수정**: 폰 변형의 `maxHeight` 캡 제거(데스크톱·모바일 모두) + `objectFit: contain` — 자연 비율 렌더
- **검증**: 실측 — 세로 이미지 798×1986px(자연비 0.402)로 렌더

## 4. ✅ 해결 (2026-09-09): 프로젝트 상세: 데스크톱 초기 렌더 시 앱바·콘텐츠 겹침(꿈틀)

- **원인**: `PortfolioClientShell`이 `useSyncExternalStore` 하이드레이션 게이트로 pathname을 하이드레이션 이후에만 읽도록 되어 있었음. SSR/프리렌더 시 `isProjectPage = false` → `padding-top: 2rem`으로 렌더되고, 하이드레이션 후 `is-project` 클래스 적용(`padding-top: 0 !important`)으로 데스크톱에서 32px CLS 발생
- **수정**: 게이트 제거 + `usePathname()` 직접 사용. 프록시 rewrite(`/ko` 프리픽스 추가)는 `stripLocalePathPrefix`로 정규화되므로 서버·클라이언트 간 `isProjectPage` 값이 불변 — hydration mismatch 없음 (커밋 d23628a)
- **잔여(별도 이슈)**: 매소너리 `<img>` aspect-ratio/치수 예약 → 아래 항목 11

## 5. 프린트 미리보기 여백·디자인

- **증상**: /print 프린트 화면 미리보기 여백 없음·어색
- **원인**: 프린트 전용 스타일시트(PrintableResume/PrintablePortfolio)가 테마와 의도적으로 분리된 자체 설계 — 여백·레이아웃 미세 조정 부족
- **권장 수정**: 프린트 CSS 재설계 — `@page` 여백, 카드 간격, 타이포 밀도 조정

## 6. ✅ 해결 (2026-08-15): 모바일 테이블 가로 넘침

- **원인**: `globalStyle(`@media ...`)` 패턴이 점 없는 클래스명을 생성해 모바일 카드 변환 규칙이 무효였음 (5곳: CompanyCard·ProjectDetailPage×2·ProjectLightbox·MermaidDiagram). 추가로 모바일 카드 라벨용 `data-label`이 없었음
- **수정**: 미디어 블록 5곳을 정식 `'@media'` 키 패턴으로 재작성 + `rehypeTableLabels` 플러그인 신설(thead→td data-label, 테스트 3건) + next.config 등록
- **검증**: 실측 — 테이블 카드 변환 적용, 가로 넘침 0, 라벨 렌더

## 7. ✅ 해결 (2026-08-15): 한국어 MDX `**"..."**` 리터럴

- **원인**: CommonMark 규칙상 닫는 `**` 앞이 구두점(따옴표)이고 뒤가 글자면(`"**가`) 닫힘으로 인정 안 됨 — 줄 끝 닫힘은 정상
- **수정**: aira·camerafi·agentic-workflow ko MDX 3곳에서 강조 내부 따옴표 제거
- **검증**: aira ko 회고 5번 `<strong>` 렌더 확인

## 8. ✅ 수정 (2026-08-15): iOS Safari 하단 내비 필 점프 — 배포 후 재검증 필요

- **원인**: 스파이가 "임계선 위의 마지막 섹션"을 선택 — iOS Safari에서 프로그래매틱 스크롤이 살짝 어긋나게 정착하면 직전 섹션이 선택됨
- **수정**: "임계선에 가장 가까운 섹션" 선택으로 변경 (`useScrollSpy.ts`) — 실측: Skills 클릭 후 필 유지 확인
- **후속**: 배포 후 iOS Safari에서 재확인

## 9. ✅ 수정 (2026-08-15): 프로덕션 이미지 미표시 — 배포 후 재검증 필요

- **원인**: 프로덕션에서 로컬 이미지가 vinext `/_next/image` 옵티마이저로 라우팅됐는데, 이 배포에 해당 엔드포인트가 연결되어 있지 않아 404. 동영상은 옵티마이저를 우회(early return)해서 정상이었음
- **수정**: 로컬 이미지도 public/ 스태틱 자산으로 직접 서빙 (`image.ts`) — 테스트 갱신
- **후속**: 배포 후 프로덕션에서 스크린샷 렌더 확인

## 10. ✅ 해결 (2026-09-09): 홈 프로젝트 행(resume 변형): 한줄 소개와 기술스택 레이아웃 재배치

- **증상(사용자 보고)**: "프로젝트 한줄 소개 문구 바로 다음에 사용하는 주요 기술스택이 쓰여있는데 이거 레이아웃 재배치"
- **원인**: resume 변형의 `resumeDescription`이 `·` 구분자와 `mainSkillsLabel`(언어+프레임워크)을 문장 안에 인라인으로 이어 붙임 — 소개 문구와 기술스택이 같은 회색 텍스트로 붙어 계층·구분이 없음
- **수정(방향 ① 적용)**: 인라인 세그먼트 제거. 기술스택은 기존 스킬 칩 행(spotlight와 공유하는 `skills` 스타일)으로만 표시 — 홈 내 일관성 확보. 죽은 스타일(`descSeparator`·`mainSkills`)과 미사용 연산 제거. 렌더 테스트 2건 추가
- **검증**: vitest 217/217, tsc, 브라우저 실측(스냅샷) — 설명 문단에 기술스택 없음, 칩 행 분리 확인
